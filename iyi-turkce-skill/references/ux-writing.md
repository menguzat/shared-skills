# Turkish UX writing

## UX copy is interface behavior

Evaluate a string by what it helps the user do, not by literary elegance.

## Component order

### Button
Action.

### Field label
Information requested.

### Helper
Format/reason/constraint.

### Error
Problem + recovery.

### Confirmation
Object + consequence.

### Toast
Outcome; next action only if useful.

## Verbs

Use the verb closest to the actual operation.

`Gönder` is better than `Devam` if the action submits.
`Kaydet` is better than `Tamam` if the action saves.

## Error tone

Do not perform empathy theatrically.

Avoid:
`Üzgünüz! Olamaz! Bir şeyler ters gitti 😔`

Prefer useful information:
`Ödeme alınamadı. Kart bilgilerinizi kontrol edin veya başka bir kart deneyin.`

Only state a cause the system actually knows.

## Person

Turkish UI can often avoid explicit `siz/sen`.

`E-posta adresinizi girin.` is already direct.
`Lütfen` is not required on every instruction.

Use `lütfen` when a request imposes effort, asks permission, or benefits from courtesy—not as punctuation.

## Destructive actions

Object-specific copy:
`Hesabı sil`
rather than:
`Onayla`

Confirmation:
`Hesabınız ve kayıtlı verileriniz silinecek. Bu işlem geri alınamaz.`

## Empty state

Don't turn every empty state into a joke.
Provide orientation and action.

## Consistency

A product term is not a synonym-writing opportunity.

If the object is `proje`, do not cycle through:
`proje`, `çalışma`, `iş`, `dosya`
unless they mean different things.
