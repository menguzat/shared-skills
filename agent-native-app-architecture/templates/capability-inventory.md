## Capability quality checks

- Name describes an action/outcome, not a page.
- Input schema is explicit.
- Output is machine-verifiable where possible.
- Read/write behavior is unambiguous.
- Server-side authorization is defined.
- High-consequence mutations have a review policy.
- Repeated execution behavior is known.
- UI representation is optional; capability is not coupled to one fixed screen unless necessary.
